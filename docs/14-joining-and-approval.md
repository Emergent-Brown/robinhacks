# Joining and organizer approval

**Join the event** opens the event registration form. For app access, attendees and organizers open [emergenthacks.com](https://emergenthacks.com/) and select **Sign in → Continue with Google**. Google supplies their email; a new attendee confirms their name and sends an access request. They do not need to choose a team or set a password. Staff applicants can choose the judge or organizer request path. New competing-team requests close when the first funding round opens. Completing the registration form does not create or approve an app account.

Requests stay pending until an organizer reviews them. The attendee can use **Check status** to make a fresh request and see when it was checked; an approval also updates the page automatically through the membership listener. An attendee must use the same Google account on return. A verified email establishes identity but does not itself grant access.

## For organizers

1. Select **Sign in → Continue with Google**, choose the already-approved organizer account, and open **Admin → Access**. On mobile, Admin is under **More**. An organizer can also open [the admin page](https://emergenthacks.com/#/platformadmin) directly after signing in.
2. Select **Refresh requests**. Review the applicant's verified email against the roster; every applicant is still pending at this point.
3. For a participant, select an existing team or enter a new team name. Approving for an existing team adds a member; approving a new team creates it with the applicant as captain. Review the explicit confirmation and approve.
4. Judge and organizer requests have their own staff approval; use those only for people you intend to give staff permissions.
5. Ask the attendee to select **Check status** if their page has not updated automatically.

Only an approved organizer can approve. The server checks the organizer role, the applicant's verified email, event phase, roster lock, and team limits in the same transaction. New team creation remains restricted to registration. An applicant cannot approve themselves or acquire staff permissions through their own request. Each action is audited.

Existing email/password accounts may still sign in using the secondary sign-in option; new registration uses Google.
